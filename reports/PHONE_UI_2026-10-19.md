# 휴대폰 앱 UI · 2026-10-19

메시지 팝업과 각각의 기능 창을 휴대폰으로 통합했다. 홈의 16개 앱에서 기능을 열며, 상점·옷장·일정·달력·저장·설정 및 확인 화면은 같은 휴대폰 테두리 안에 표시한다. 스크롤은 앱 본문 안에서만 이루어지고 상태 표시줄, 제목, 홈 막대는 고정된다. 기존 기능 진입점도 공통 창을 사용하므로 같은 휴대폰 화면을 연다.

메시지에는 홈 알림과 앱 배지가 표시된다. 목록 → 대화 → 답장/스티커 흐름을 유지하며, 답장 후 자동으로 닫지 않는다. 뒤로 버튼과 Escape는 대화 → 목록 → 홈 → 닫기 순서로 이동한다. 기능 앱의 하단 막대는 홈, 상단 닫기는 게임으로 돌아간다. 이야기·데이트 본편과 잠깐 대화는 기존 전체 화면 연출을 유지한다.

새 파일 `src/phone.css`에서 휴대폰 내부의 상품, 옷장, 활동 카드와 달력을 재배치했다. 새 이미지나 외부 의존성은 없으며, 아이콘은 문자와 로컬 SVG 경로로 구성했다. 저장 스키마·비용·게임 규칙은 변경하지 않았다. 기존 PC 전용 정책을 유지한다.

## 검증

- Node `tests/run-core.mjs`: 9개 로직 모음, 총 101개 통과. 에셋 경로 79개 모두 존재.
- Chrome `tests/phone-browser.mjs`: 실제 마우스/키보드 입력으로 홈 앱 16개, 기능 화면 15개와 홈 복귀, 낮은 PC 해상도의 본문 넘침, 안 읽은 메시지, 답장 저장·스티커 유지, Escape 탐색, 이야기 전체 화면 전환·기능 복귀 검사.
- 기존 `tests/somesome-ui.html`: 회차 보너스·관계·설정·빠른 저장/불러오기·일정 일괄 실행·주간 결산·일터 방문·메신저 이모티콘 통과.
- PC 1440×900 및 1280×720. 브라우저 런타임 예외 없음. 결과: [JSON](../qa/phone/results.json), [홈](../qa/phone/home-1440.png), [상점](../qa/phone/shop-1440.png), [메시지](../qa/phone/messages-1280.png).
- Windows WebView2 실행 파일 자체와 모바일 기기는 이번에 플레이 테스트하지 않았다. 성능 벤치마크는 수행하지 않았다.
- 기존 `dist/AquaLuna/game`에도 변경한 `index.html`, `src/app.js`, `src/phone.css`를 복사하고 원본과 SHA-256 일치를 확인했다. 실행 중인 앱은 다시 열어 새 화면을 불러올 수 있다.

자동 검사는 별도의 임시 Chrome 프로필을 사용하며 사용자의 플레이 저장에 접근하지 않는다.
