# Aqua Luna 졸업작품 제출 준비 점검

> 후속 수정: 아래 점검 이후 나리 진 결말의 약속 회상 분기를 바로잡고, 임시 배경음악 3곡과 출처 표시를 추가했다. 실제 청감 검토와 Windows 패키지 실기 검증은 아직 남아 있다. 이 문서의 발견 사항은 당시 점검 결과다.

검토일: 2026-11-02. 학교·학과의 평가표, 제출 형식, AI 사용 규정은 제공받지 못했다. 아래는 현재 프로젝트를 기준으로 한 기술·작품 완성도 판단이며 합격이나 점수를 예측한 것은 아니다.

## 판단

브라우저에서 소개하고 핵심 루프를 시연할 수 있는 졸업작품 프로토타입이다. 다만 사운드 부재, 결말의 서사 연속성, 배포 파일과 실제 기기 검증 때문에 현재 그대로를 최종 완성본으로 제출하기에는 위험하다. 학교가 미완성 프로토타입과 브라우저 실행을 허용하는지, 제작 과정에서의 AI 사용 표기가 필요한지는 별도로 확인해야 한다.

## 주요 발견 사항

1. **높음 — 배경 음악이 실제로 없다.** `src/campus-v2/audio.js`는 세 MP3를 요청하지만 `assets/audio` 디렉터리와 세 파일이 없다. 오류는 조용히 무시되므로 설정에 BGM 음량이 보여도 음악은 나오지 않는다. 음악과 라디오가 중요한 서사이므로 시연 몰입도에 직접 영향을 준다. 음악을 추가할 경우 `scripts/build-exe.ps1`의 복사 대상에도 `audio`를 추가해야 한다.
2. **높음 — 나리 진 결말에서 하지 않은 약속을 언급할 수 있다.** `endings.js`의 진 결말은 `nariDecisionTrusted`를 요구하지 않지만, 해당 플래그를 만드는 선택지에서 한 말을 항상 회상한다. 구성한 테스트 상태에서 `nariDecisionTrusted=false`인데 진 결말이 해당 약속을 언급함을 재현했다. 실제 전체 플레이를 통한 해당 조합의 도달은 별도로 검증해야 한다.
3. **높음 — 제출용 Windows 실행 파일이 준비·검증되지 않았다.** `dist`에 현재 빌드가 없으며 프로젝트는 .NET 10 Windows/WebView2를 사용한다. 이 환경에는 .NET 6·7·9 SDK만 있고 PowerShell도 없어 기존 Windows 빌드 스크립트를 실행하지 않았다. 현재 코드로 만든 EXE의 깨끗한 Windows PC 실행·저장·복원·오프라인 동작은 미검증이다. HTML 브라우저 시연을 허용하는 제출 방식이라면 이 항목의 영향은 달라진다.
4. **중간 — 캐릭터 감정 연출과 결말 완성도가 부족하다.** 의상 그림은 여러 벌이나 `wardrobe.js`의 표정 사전은 비어 있다. 결말은 작동하는 첫 대본이며, 각 인물의 사건을 충분히 회수하는 긴 에필로그·전용 결말 연출 및 모든 경로의 직접 플레이 검토가 남았다.
5. **중간 — 완료 후 감상 경로가 제한적이다.** 결말 완료 후 이어하기는 완료 안내창으로 돌아오며, 완료 세이브에서 결말을 다시 읽거나 앨범을 열 수 있는 전용 경로는 확인되지 않았다. 별도 수동 저장이 있다면 그 시점으로 돌아갈 수 있다.
6. **중간 — 제작·사용권 증빙 및 제출 문서 정리가 필요하다.** 폰트 두 종류의 라이선스 파일과 여러 이미지 생성 기록은 있다. 하지만 제출할 전체 자산의 출처·사용 조건·기여자·AI 사용 내역을 한곳에서 확인할 수 있는 제출용 크레딧/명세는 확인하지 못했다. 학교 규정과 자산별 조건을 확인해 제출 문서로 정리해야 한다.
7. **중간 — 분량과 재미에 대한 외부 검증이 없다.** 362일 자동 진행은 한 가지 전략의 진행 가능성을 확인한 것이며, 사람의 플레이 시간·반복 피로·루트별 만족도나 모든 엔딩 도달을 증명하지 않는다. 첫 학기 시뮬레이션도 3개 시드의 모델 기반 검사로, 게임 전체나 화면 품질의 직접 검증은 아니다.

## 이번에 확인한 것

- `node --test tests/campus-v2*.test.mjs`: 12개 테스트 파일 통과. 그중 실제 게임 핸들러를 DOM 모형에서 실행한 런타임 검사 57개, 362일 자동 진행 1경로, 자산 경로 검사 76개 포함.
- `node tests/campus-v2-semester-sim.mjs`: 3개 시드와 4개 전략의 첫 학기 모델 시뮬레이션 통과. 실제 브라우저 플레이와는 다르다.
- Safari의 테스트 전용 메모리 저장 미리보기에서 새 게임 인트로, 3월 9일 학교 장면과 수업 후 장소 목록·카페 미리보기, 서진 결말 장면과 완료창을 확인했다. 장소 미리보기에 만날 인물은 표시되지 않았다. 이는 일부 장면의 데스크톱 화면 확인이며 전 루트·해상도·실제 저장 파일 검증은 아니다.
- 게임의 최신 나리 입화는 v6, 성탄 CG는 v2를 계속 참조한다. 사용 중인 76개 자산 경로 검사도 통과했다.
- `archive/nari-previous-illustrations/`에 기존 구 일러스트 8장과 Git HEAD에서 복원한 v3 네 장을 보관했다. 12개 파일의 SHA-256을 `manifest.json`과 대조했다. 삭제되어 있던 v3는 작업 트리의 최종 상태가 아닌 Git HEAD 복원본이다.

## 제출 전 우선순위

1. 실제 제출 형식과 교수자 평가 기준, AI 활용·출처 표기 기준을 확인한다.
2. 나리 진 결말을 포함한 실제 선택 이력과 대사 연속성을 고치고, 세 히로인 주요 루트를 처음부터 엔딩까지 사람 손으로 플레이한다.
3. 최소한의 적법하게 사용할 수 있는 배경 음악을 적용하고, 실제 제출 패키지에 포함되는지 소리까지 확인한다. 표정·감정 연출과 결말을 보강한다.
4. 제출 대상 Windows PC에서 새 실행 파일을 빌드해 실행·저장·종료·재실행·오프라인·화면 크기를 점검하거나, 학교가 브라우저 제출을 허용하면 제공 방식과 실행 환경을 명확히 문서화한다.
5. 제작자·역할·도구·에셋 출처와 라이선스·AI 활용, 실행 방법, 시연 동선 및 알려진 한계를 한 장의 제출 안내로 정리한다. 제3자 플레이 테스트에서 소요 시간과 반복 피로를 기록한다.
