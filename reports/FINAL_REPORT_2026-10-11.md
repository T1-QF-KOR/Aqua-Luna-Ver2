# Aqua Luna 최종 작업 보고서

작성일: 2026-10-11 (Asia/Seoul)

## 결과

PC 전용 화면 변경에 이어 능력치 육성·일정 예약·조건부 대화와 헤드셋 자유 착탈을 게임에 연결했다. 로직 테스트 66개와 게임 참조 이미지 79개의 존재 검사가 통과했다. 실제 브라우저의 최종 화면·자동 클릭 검증은 도구 연결 오류로 완료하지 못했다. 따라서 화면까지 검증된 배포 완료 상태로 판정하지 않는다.

## 구현한 시스템

| 기능 | 동작 |
| --- | --- |
| 능력치 | 주인공의 지식·체력·감수성, 각 0~100 |
| 육성 | 공부·운동·음악 감상은 시간 1칸, 기력 10/20/10을 사용해 해당 능력치 +4 |
| 아르바이트 | 기존 임금·시간·기력 규칙 유지. 카페는 감수성, 편집은 지식, 행사 보조는 체력 +2 |
| 일정 | 하루 3칸 범위에서 예약하고 다음 일정을 하나씩 실행. 예약 자체는 무료 |
| 실행 검증 | 실제 실행 시 자원·진행 중인 대화/체험을 재검사. 실패하면 자원과 예약 유지. 오래된 클릭은 중복 실행 방지 |
| 날짜 | 다음 날 시간·기력 회복 및 남은 예약 초기화. 기존 하루 1회 데이트 제한 유지 |
| 조건부 이벤트 | 2일째 및 해당 능력치 8부터 악보·산책·음악 이야기 3개가 추가로 열림 |
| 선택지 | 능력치 12의 특별 응답은 호감 +3·신뢰 +2·기분 +8. 경청은 신뢰 +1·기분 +3. 재촉은 기분 -8 |
| 비주얼 노벨 | 새 이벤트도 배경·수련 그림·표정과 텍스트 선택지로 진행. 기존 탐방·퍼즐 및 추억 다시 읽기 유지 |
| 저장 | 기존 v2 저장은 능력치 0·기분 50·빈 일정으로 보완. 경제·의상·이야기 기록 유지 |

기분 변화는 이번에 추가한 육성 이벤트 3개에 적용했다. 전체 기존 대본에 기분 수치를 일괄 부여하지 않았다. 육성 이벤트는 선택형 추가 콘텐츠이며 기존 연애·우정 엔딩의 필수 조건을 늘리지 않았다. 전체 게임에 새로운 마감일이나 강제 실패 엔딩을 넣지 않았으며, 하루 행동 시간과 이벤트 해금 날짜로 시간을 관리한다.

## 헤드셋

- `ownedNeckAccessories`와 `neckAccessory`로 의상·스타킹에서 분리했다.
- 기본 보유, 기본 미착용. 옷장에서 모든 의상에 무료로 착용·해제한다.
- 데이트 출발 준비에서도 미리 선택할 수 있다. 취소하거나 출발 조건이 맞지 않으면 현재 착용 상태를 바꾸지 않는다.
- 의상 변경, 다음 날, 저장·불러오기 후에도 선택을 유지한다.
- 진행 중인 이야기·체험에서는 착탈을 잠시 잠가 출발 스냅샷과 화면의 불일치를 막는다.
- 데이트·추억·첫 탐방 기록에는 당시 헤드셋 상태를 저장한다. 이전 기록에 헤드셋 필드가 없으면 미착용으로 표시한다.
- 독립 헤드셋 아이콘, 14종 기본 전신 및 캐주얼 6개 포즈의 착용/미착용 그림을 연결했다. 기존 표정·스타킹 조합도 유지한다.

다른 신규 액세서리 22종은 개별 이미지 제작 범위다. 헤드셋과 기존 스타킹 외의 소품 전체를 개별 장착하는 시스템은 이번 범위에 포함하지 않았다.

## 아트와 PC 화면

- 실내 배경 2종: 수련의 방, 옷장·상점 피팅 공간.
- 전신 스타일 14종, 다양한 포즈·표정 6종, 개별 액세서리 23종(헤드셋 포함).
- [아트 카탈로그](../docs/art-catalog.html): 헤드셋 유무 전환, 밝은/어두운 배경, 원본 PNG 링크.
- [Figma 보드](https://www.figma.com/design/1RXvK2xXHu7Zk5OjJBtSBE): 전신 14장·포즈 6장·소품 23장 총 43장 업로드 완료. 세 보드의 스크린샷을 확인했다.
- [패션 조사·제작 기록](FASHION_RESEARCH_2026-10-11.md): 조사 출처, 선정 기준, 생성 방식과 프롬프트 보존 범위.
- 모바일 화면 분기를 제거한 PC 레이아웃을 유지한다. 관리 패널은 왼쪽, 캐릭터는 오른쪽 전용 공간에 배치하고 그림 구도에 따라 표시 크기를 구분한다.
- 기본 전신은 모든 의상에 제공한다. 니트·코트의 기존 미소/사색 그림은 원래의 부분 신체 구도를 유지하므로 별도 표시 크기를 적용한다.

새 이벤트 추가로 기존 테스트의 고정 이벤트 수를 35에서 38로 수정했다. 캐주얼 표정 수는 새 포즈를 반영해 5에서 7로 변경했다. 테스트를 통과시키기 위해 기존 엔딩·구매·시간·퍼즐 조건을 완화하지 않았다.

재현: Node.js 18 이상에서 `node tests/run-core.mjs`. 이번 실행은 제공된 Node REPL에서 해당 모듈을 실행했다. 브라우저 DOM을 구현한 테스트가 아니라, 결과 출력 요소와 localStorage만 대체한 VM 기반 로직 테스트다.

## 미검증 사항

CUA에서 연결된 브라우저가 없었고 Safari 선택은 `cgWindowNotFound`로 실패했다. 이 환경에서 브라우저 최종 화면의 HUD 비가림, 1280/1440/1920 해상도 배치, 실제 버튼 클릭·모달·키보드 이동을 재검증하지 못했다. 이전 `qa/pc-only-results.json`은 이번 변경 전체의 테스트 결과로 사용하지 않았다.

실제 플레이 시간·장시간 체감 밸런스는 자동 테스트로 입증하지 않았다. 미니게임 해결 가능성 검사는 사람의 플레이테스트 시간을 뜻하지 않는다.
