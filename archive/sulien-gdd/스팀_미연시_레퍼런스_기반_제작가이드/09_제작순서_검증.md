# 09. 제작 순서와 검증

[목차](README.md) · 향후 구현 담당자를 위한 작업 기준 · 이번 작업은 문서 작성만 수행

## 첫 제작 범위

아래 수량은 첫 검증용 제안이며 전체 콘텐츠 규모나 출시 약속이 아니다. 실제 제작 시간·예산은 산정하지 않았다.

| 구성 | P0 범위 | 완료 판정 |
| --- | --- | --- |
| 도입·초반 교류 | EV-01~07의 7개 단위 | 목표 선택·대면·메시지를 포함. 모두 VN 장면 7편이라는 뜻은 아님 |
| 개인 활동 | ACT-01·ACT-02 | 각 활동을 시작·선택·완료·저장·재개 가능 |
| 수집 | COL-01·02와 공유 이력 | 혼자 얻은 결과를 공유한 경우에만 후속 반응 |
| 장소 | 강의실·연습실·강변을 중심으로 시작 | 첫 인사와 개인 활동 동선. 식당 재회는 기존 배경 적합성 검토 |
| 외출 | 기존 무료 산책 한 코스 연결 | EV-07에서 확정 출발, 비용·완료 정산은 한 번 |
| 관계 | R0→R1→R2→R3 진입 | 사건과 다른 날의 교류로 연결, 즉시 연인 전환 없음 |
| 기록·편의 | 기존 저장·불러오기·회상·설정 활용 | 이전 저장 보존, 새 미완료 상태 재개 |
| 조연 부탁 | Q-01 안내 문구만 | 독립 퀘스트 시스템은 P1로 남김 |

P0 결과를 판단할 질문은 ‘플레이어가 혼자 하루를 시작하고, 수련을 만나 관계를 쌓았다고 느끼는가’다. 체험 수나 플레이 시간 숫자를 늘리는 것은 별도 목표로 본다.

## 상태 계약 초안

다음은 논리적으로 필요한 정보다. 실제 필드명과 직렬화 형식은 구현 때 결정한다.

| 정보 | 포함할 내용 | 검증 원칙 |
| --- | --- | --- |
| 시작 경로 | 이전 친구 경로 / 새 첫 만남 경로 | 누락된 옛 저장을 새 시작으로 추정하지 않음 |
| 플레이어 목표 | 허용된 목표 ID | 자유 문자열이 필요하면 길이·출력 처리 검증 |
| 만남 이력 | 최초 인사·연락처·공동 사건 | 기록되지 않은 만남을 가짜 완료로 추가하지 않음 |
| 미완료 활동 | ID·콘텐츠 버전·진행 단계·선택·시작 시 정산 정보 | 허용된 입력·중복 지급·날짜 일치 검증 |
| 개인 기록 | 결과 ID·선택·장소·최초 날짜 | 단기 일지 삭제와 무관하게 보존 |
| 공유 이력 | 기록 ID·공유 사건·수련 응답 | 소유하지 않은 기록 공유, 보상 재지급 거부 |
| 현재 장면 | 혼자/대면/메시지·등장 인물 | 마지막 데이트를 오늘의 동행으로 복원하지 않음 |
| 약속 | 제안·응답·확정·이행·재조정 | 예약과 출발 비용을 구분 |

현재 이야기·체험 진행과 새 개인 활동은 동시에 활성화하지 않는 방향을 권한다. 편집 가능한 저장 파일은 안전하지 않은 입력으로 검증하며 이미지 경로나 실행할 코드를 파일에서 그대로 받아들이지 않는다.

## 이전 저장과 새 시작의 공존

기존 저장은 그동안 친해진 관계와 선택을 유지한다. 새 첫 만남을 자동 재생하거나 기존 `uni-p01` 등 완료 사건의 뜻을 바꾸지 않는다. 새 도입에는 별도 사건 ID 또는 명시적인 콘텐츠 버전을 둔다. 기존 `hello` 등의 별칭이 대학 사건을 가리키므로 첫 인사·연락처 조건을 이름이 비슷하다는 이유로 같은 것으로 취급하지 않는다.

새 게임은 첫 만남 경로, 기존 이어하기는 이전 경로로 읽히도록 설계한다. 도입 건너뛰기는 설명·읽기만 생략하며 사건 이력을 위조하지 않는다. 저장 형식 변경이 필요하면 이전 형식 읽기·새 형식 쓰기·손상 파일 거부를 함께 검증한다.

미완료 활동을 불러오면 시작 비용은 재차 차감하지 않고, 완료 보상은 한 번만 적용한다. 기록만 다시 읽으면 날짜·호감·자원이 바뀌지 않는다. 새 게임을 만들기 전에 이전 진행을 자동으로 덮는 문제도 기존 확인 흐름과 함께 검토한다.

## 의미 있는 검증 시나리오

| ID | 실행 경로 | 통과 기준 |
| --- | --- | --- |
| T01 | 새 게임→개인 도입 | 이름·개인사·연인 메뉴가 선공개되지 않음 |
| T02 | 안내 건너뛰기 | 수련과 아직 만나지 않은 상태 유지 |
| T03 | 개인 활동 후 첫 인사 | 필수 만남이 소멸하지 않고 선택 가능 |
| T04 | 첫 인사→다음 날짜→연락처 | 단계 건너뛰기 없이 메시지 접근 개방 |
| T05 | 혼자 활동·귀가·메시지 | 대면하지 않는 장면에서 수련 입상 숨김 |
| T06 | 활동 시작→닫기→저장·새로고침→재개 | 같은 선택·지급 상태, 이중 비용 없음 |
| T07 | 같은 선택 더블클릭·오래된 버튼 | 완료·보상 한 번, 잘못된 다음 입력 거부 |
| T08 | 기록 미공유/공유 저장 비교 | 해당 후속 회상이 정확히 달라짐 |
| T09 | 낮은 능력·힌트·체험 도움 경로 | 기본 관계 진행과 약속 도달 가능 |
| T10 | 연락 보류·며칠간 개인 생활 | 정상 재진입, 영구 잠금 없음 |
| T11 | 이전 저장·옛 미완료 이야기 | 첫 만남 강제 삽입·선택 손실 없음 |
| T12 | 손상된 ID·단계·보상 기록 가져오기 | 오류 안내, 기존 정상 진행 보존 |
| T13 | 산책 초대→취소→확정→완료 | 출발 전 비용 없음, 출발·완료 정산 한 번 |
| T14 | 회상·수집 재열람 | 실제 상태와 일일 제한 변경 없음 |
| T15 | 큰 글자·움직임 줄이기·키보드 | 선택·저장·나가기 접근, 가림·초점 유실 없음 |
| T16 | 우정·보류와 연간 경로 연결 | 연인 전용 문구 누출·조건 충돌 없음 |

첫 구현 때 기존 로직 회귀 테스트와 새 경로 상태 테스트를 함께 수행하고 실제 브라우저에서 화면을 확인한다. 문서 작성만 한 이번 작업에서는 게임 테스트를 실행하거나 통과했다고 주장하지 않는다.

## 플레이 검토 질문

한 번은 빠른 관계 진행, 한 번은 개인 활동 중심, 한 번은 도움 기능과 연락 보류로 진행한다. 각 플레이에서 ‘왜 수련을 다시 만나고 싶은가’, ‘수련이 없는 시간에도 할 일이 있는가’, ‘지난 선택을 기억하는 장면이 있는가’를 확인한다. 콘텐츠 수만 맞았다는 이유로 P1을 확대하지 않는다.
