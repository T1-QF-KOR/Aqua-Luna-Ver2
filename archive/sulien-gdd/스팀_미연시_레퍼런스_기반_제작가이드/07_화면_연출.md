# 07. 화면과 연출

[목차](README.md) · Aqua Luna용 제안 · 관련 F01·F05·F14·F15·F16·F22

## 화면이 말해야 하는 것

플레이어가 지금 어디에 있고, 혼자인지 누구와 함께인지, 무엇을 할 수 있는지를 알 수 있어야 한다. 모든 화면에 수련 이미지를 배치하는 방식에서 벗어나, 수련을 만났을 때 등장 자체가 의미를 갖도록 한다. 이것은 사용자 요청에 따른 제안이며 참고 게임 모두가 같은 표시 정책을 쓴다는 뜻이 아니다.

화풍은 기존 배경·인물의 차분한 색과 고운바탕·Pretendard를 우선 유지한다. 기존 PC 전용·최소 1280×720 목표를 따른다. 모바일 레이아웃이나 새 3D 엔진을 전제하지 않는다.

## 화면 상태와 등장 정책

| 상태 | 중심 화면 | 수련 표시 | 주요 버튼·정보 |
| --- | --- | --- | --- |
| 타이틀 | 플레이어가 향할 캠퍼스/길의 분위기 | 홍보용 그림 선택 가능. 현재 동행처럼 표현하지 않음 | 새 학기 시작·이어하기·설정 |
| 개인 도입 | 통학길·시간표·내 독백 | 등장 전 숨김 | 목표 선택·수업으로·안내 건너뛰기 |
| 개인 일상 | 현재 장소와 내 다음 할 일 | 숨김 | 내 시간·기력·돈·캠퍼스·휴대폰 |
| 캠퍼스 선택 | 장소와 오늘 할 수 있는 일 | 전체 인물 대신 약속 정보 | 장소·활동 비용·잠금 이유 |
| 첫 만남/대면 이야기 | 장소·상대·대사 | 장면 등장 시 표시 | 대사·선택·기록·저장 |
| 메시지 | 대화 스레드 | 대면 입상 숨김, 연락처 교환 뒤 프로필만 | 답장·나중에·이전 대화 |
| 개인 근무 | 작업 공간과 도구·내 결과 | 방문 사건 때만 별도 표시 | 근무·선택 체험·정산 |
| 회상·앨범 | 당시 장면의 기록 | 당시 상황에 맞는 이미지 | 읽기 전용·돌아가기 |

이미지 표시를 호감도 하나로 판단하지 않는다. 같은 배경에 있다는 이유만으로 동행으로 판단하지 않는다. 모달 닫기·다음 날·저장 불러오기 후에도 장면과 등장 상태가 맞아야 한다.

## 일상 화면의 정보 순서

상단에는 날짜·현재 장소, 한쪽에는 돈·시간·기력을 모은다. 중앙 배경은 장소가 보일 정도로 비워 둔다. 짧은 내 생각이나 현재 목표 하나만 기본 노출한다. 세부 관계·수집·예산·설정은 휴대폰이나 메뉴에서 연다.

아직 수련을 만나지 않았다면 ‘수련 호감 0’보다 ‘오늘의 목표: 첫 전공 수업 찾기’가 먼저다. 관계 노트는 첫 만남 뒤 인물 기록이 생기고, 연락처는 교환 사건 뒤 생성된다. 오래된 친구라는 단계 표시를 새 게임 기본값으로 쓰지 않는다.

## 행동의 이름도 상황을 따른다

| 현재의 표현/상황 | 제안 표현 | 목적 |
| --- | --- | --- |
| 새 게임부터 수련과 보내는 하루 | 나의 하루 / 나의 새 학기 | 생활의 주체를 명확히 |
| 만나기 전 데이트 초대 | 첫 수업에 가기 | 아직 가능한 행동만 안내 |
| 연락처 교환 직후 데이트 | 같이 점심 먹을지 묻기 / 짧게 걷자고 하기 | 관계 속도에 맞는 언어 |
| 함께할 내일을 위한 노력 | 오늘의 근무 / 내 생활비 | 플레이어의 독립된 생활 |
| SD 수련의 작업 노트 | 나의 근무 기록 | 누가 일하고 있는지 일치 |
| 수련의 옷장을 언제든 조작 | 외출 준비에서 함께 코디 고르기 | 관계가 생긴 뒤의 공동 준비로 맥락화 |
| 마음을 수치로 모두 공개 | 알게 된 사실과 최근 교류 | 아직 모르는 마음을 남김 |

코디 시스템은 삭제보다 접근 시점·표현을 검토한다. 이미 보유한 의상과 앨범의 과거 코디는 보존한다. 의상 해금에 새 관계 조건을 넣는다면 이전 저장 사용자에게 소유품을 잃게 하지 않는다.

## 대면 장면의 리듬

등장 이전에는 배경과 관찰 → 누군가의 말 → 상대의 모습 → 이름 소개 → 플레이어 선택 → 상대 응답 → 헤어짐 순서로 설계할 수 있다. 첫 인사 전부터 개인사와 속마음을 긴 설명으로 보여 주지 않는다.

표정은 발화와 연결하고 클로즈업은 의미 있는 순간에만 쓴다. 관계 상승은 서로의 말을 다시 기억하는 짧은 응답과 함께 표현한다. 호감·신뢰 변화 알림은 읽기를 가리지 않고 사용자가 끌 수 있는 방향을 권한다.

## 음향·CG·추가 에셋 우선순위

P0에서는 현존 배경과 표정의 적합성을 확인하고 텍스트로 기본 흐름을 검증한다. 실제 배경이 없는 새 장소는 임시안이라고 명확히 표시한다. 제작 가이드가 있다고 필요한 이미지·음성까지 완성된 것으로 취급하지 않는다.

P1 후보는 첫 수업 배경, 플레이어 개인 생활 공간, 사진 수집용 장면 변형이다. P2 후보는 첫 자발적 초대·마음 확인 CG와 핵심 음성이다. 모든 장면 풀보이스나 Live2D 제작을 초반 전환의 선행 조건으로 두지 않는다.

음악 감상과 가사 콘텐츠는 자체 제작·허가한 자료를 사용한다. 소리 없이도 단서와 진행을 알 수 있어야 하며 실제 가창을 마이크로 평가하는 기능은 범위 밖이다.

## 조작·읽기 완료 기준

Tab·Enter·Space·Esc가 서로 다른 상태에서 의도대로 작동한다. Esc는 닫기이며 활동 기록 삭제가 아니다. 반복 확인·취소·더블클릭으로 자원이 두 번 쓰이지 않는다. 자동 읽기는 선택을 대신 고르지 않는다. 움직임 줄이기·글자 확대에서 대사와 선택지가 화면 밖으로 밀리지 않는다. 휴대폰 안에 복잡한 캠퍼스 지도까지 억지로 넣기보다 필요하면 별도 넓은 패널로 연다.
