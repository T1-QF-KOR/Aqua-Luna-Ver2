# 11. 저장과 기술 구성

[전체 GDD 목차](README.md) · 기준일 2026-10-07 · v0.1

## 지원 플랫폼

2026-10-12 확정: **PC 전용, Steam 출시 목표**. 아래 브라우저 실행 방식은 현재 개발판의 기술 구성이다. 모바일 버전은 개발하지 않는다. Steam용 데스크톱 실행 파일·저장 경로·배포 설정은 [출시 준비 문서](../docs/PC_STEAM_RELEASE.md)에 별도 관리한다.

PC 브라우저 전용이며 모바일·태블릿 지원과 모바일 전용 CSS 분기는 제거한다. 최소 화면은 1280 × 720, 권장은 1440 × 900 이상이다. 마우스·키보드를 사용하며 창을 줄여도 PC 배치를 유지한다. 저장 형식과 기존 진행 데이터는 그대로 유지한다.

## 저장 — 구현

- 자동 저장과 수동 저장 3칸, JSON 파일 내보내기·가져오기를 제공한다. 파일 가져오기 제한은 1 MiB다.
- 진행은 현재 브라우저의 `localStorage`에 저장한다. 계정·클라우드 동기화는 없다.
- 저장 실패 시 현재 창의 진행을 메모리에 유지하고 파일 백업 안내를 표시한다. 창 종료·새로고침까지 영구 보호하는 방식은 아니다.
- 가져온 파일은 적용 전 검증한다. 잘못된 자금·보유 의상·선택·체험 입력 기록 등을 거부한다.
- 기존 v2 저장의 누락된 탐방·체험 필드는 보충한다. 과거 저장에 존재하지 않던 대화 선택이나 방문 기록을 임의 생성하지 않는다.
- 설정은 게임 진행과 구분하여 유지한다. 게임 파일과 저장 파일은 외부 서버에 전송하지 않는다.

## 구현 책임

| 파일 | 책임 |
| --- | --- |
| [data.js](../src/data.js) | 경제·의상·기본 장소·그림 데이터 |
| [engine.js](../src/engine.js) | 자원 조건, 행동 전이, 대화 정산, 저장 검증 |
| [story.js](../src/story.js) | 기본 데이트·관계 대본과 사건 조건 |
| [courses.js](../src/courses.js) | 48개 탐방 코스, 방문 조건·기록 |
| [journeys.js](../src/journeys.js) | 탐방 후속 24편과 마지막 이야기 |
| [activities.js](../src/activities.js) | 퍼즐 생성·입력·완성·저장 검증 |
| [app.js](../src/app.js) 및 CSS | DOM 화면, 조작, 저장 UI, 읽기 설정, 오디오 |

HTML·CSS·JavaScript를 사용하며 프레임워크·CDN·패키지 설치 의존성이 없다. 런타임 규칙의 수치나 조건이 바뀌면 이 문서의 해당 표도 함께 갱신한다.

## 모듈 로드와 데이터 책임

`index.html`에서 data → story → courses → journeys → activities → engine → app 순서로 로드한다. 콘텐츠 정의가 먼저 준비되고 앱이 엔진과 콘텐츠를 사용해 화면을 만든다. 서버·로그인·네트워크 API는 현재 게임 실행에 필요하지 않다.

| 상태 묶음 | 주요 데이터 |
| --- | --- |
| 생활 | `day`, `ap`, `energy`, `location`, `datesToday` |
| 경제 | `money`, `totalEarned`, `totalSpent`, `expenseGoal` |
| 외형 | `owned`, `outfit`, `ownedAccessories`, `legwear` |
| 관계 | `affection`, `trust`, `story.relationship`, `story.dateCount` |
| 이야기 | `story.completed`, `story.active`, `story.preference`, `story.music`, `story.boundary` |
| 약속 | `story.promise`, `story.keptPromises` |
| 기록 | `memories`, `journal`, `story.exploration`, `story.activities` |
| 형식 | 저장 `version=2`, 이야기 `revision=1`, `savedAt` |

저장 키에는 `aqualuna.v2.` 접두사를 사용한다. 자동 슬롯은 0, 수동 슬롯은 1~3이다. 저장 덮어쓰기와 진행을 바꾸는 불러오기는 UI 확인 절차를 거친다. 파일 가져오기 도중 창을 닫거나 다른 모달로 이동하면 늦게 도착한 결과를 적용하지 않는다.

출발 때 자원을 한 번 차감하고 마지막 대화 선택 때 관계·기록을 정산한다. 동일 단계 중복 입력은 차단한다. 코드의 검증 로직을 거치지 않고 UI가 자금이나 방문 완료를 직접 확정하지 않도록 유지한다.

저장 호환 변경 시 빈 탐방 기록을 보충하는 것과 실제로 없었던 방문·선택을 생성하는 것을 구분한다. 장기 기록과 미완료 대화·체험을 함께 다루는 검증은 [QA 기준](16_QA_검증_기준.md)을 따른다.
