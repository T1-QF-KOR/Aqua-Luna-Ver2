# Aqua Luna · 비교 분석과 관계·스토리 구현

2026-10-06 / 대상: Aqua-Luna-Ver2. 사용자가 이번 작업에서 **“시스템과 스토리까지 바로 구현”**을 선택하여 검토 초안을 실제 게임으로 각색했다. 이전 보고서의 ‘게임 미반영’은 당시 상태이며 아래 내용이 최신이다.

## 비교에서 무엇을 채택했는가

외부 작품은 직접 플레이하지 않았으며, 아래는 이번에 확인한 공식 설명과 현 프로젝트 코드를 대조한 설계 판단이다. 기능의 유일성이나 상용작보다 높은 완성도를 주장하지 않는다.

**차별화의 중심:** 일해서 마련한 외출, 직접 고른 수련의 코디, 그날의 대화가 같은 앨범에 남고 다음 만남에서 회상되는 흐름. 옷의 가격을 애정의 정답으로 쓰지 않고, 음악을 다시 선택하는 수련의 결정권과 둘의 관계를 함께 다룬다. 외부 작품의 대사·이미지는 복제하지 않았다.

## 실제 플레이 흐름

1. **관계와 이야기**에서 첫 인사를 나누고 일·휴식·외출을 선택한다.
2. 외출 준비는 취소 가능하며 자원을 쓰지 않는다. 출발 시 비용·시간·기력을 한 번 사용한다.
3. 산책·카페·공연 각각 세 번 선택한다. 지난 응답을 읽은 뒤 다음 선택으로 넘어간다.
4. 마지막 선택에서 관계 수치와 앨범이 확정된다. 잘못된 선택 하나로 영구 폐쇄되는 루트는 없다.
5. 앨범에 출발 코디·시간·선택·지킨 약속이 남는다. 회상은 읽기 전용이며 보상이나 비용이 발생하지 않는다.
6. 관계 화면은 열린 이야기와 다음 단서를 안내한다. 과거 주요 사건도 다시 읽을 수 있다.

## 사건과 분기

| ID | 사건 | 개방 조건 또는 분기 |
| --- | --- | --- |
| hello | 문이 열려 있던 연습실 | 언제든 첫 인사. 듣기/일정 확인 두 응답 |
| space | 비어 있는 한 칸 | 첫 인사 + 일 또는 휴식. 선택적 일상 장면 |
| invite | 두 번 적힌 약속 | 첫 인사 + 신규 데이트 1회. 수련의 산책 제안 수락/유보 |
| score | 접힌 악보 | 제안 확인 + 데이트 3회 + 신뢰 12. 예전 곡/새 곡에 관한 대화 기억 |
| boundary | 아직 정하지 않은 일 | 악보 장면 + 데이트 4회. 의견을 묻기/대신 결정하려 하기 |
| repair | 대답을 기다리는 연습 | 대신 결정하려 했다면 개방. 사과 또는 솔직한 설명으로 회복 |
| session | 다시 부르는 이유 | 경계 확인·회복 + 데이트 5회 + 신뢰 20. 앞선 음악 선택에 맞는 도입 |
| confession | 업무가 끝난 시간 | 세션 + 데이트 6회 + 호감 18 + 신뢰 24. 연인/친구/보류 |
| revisit | 천천히 찾은 대답 | 보류 이후 추가 데이트 2회. 연인 또는 친구로 관계 확인 |
| epilogue | 너와 나란한 하루 | 관계 확인 뒤 데이트 1회. 관계별 도입 + 계속되는 일상 |

10편 전체를 한 경로에서 강제로 읽지 않는다. 회복과 재대화는 조건부이고 옥상 장면은 선택적이다. 이전 문서의 6막·12장면은 설계 초안이며 이번 실행본과 수량이 다르다. 새 날짜만 반복해서 넘겨도 주요 사건이 자동 완료되지는 않는다.

## 경제·관계 규칙

- 기존 데이트 기본 보상은 유지. 코스의 대화 선택에 따라 호감/신뢰가 최대 1~2 추가되고 실제 상한 적용 후 변화량을 표시한다.
- 새로운 호감 수치만으로 고백이 열리지는 않는다. 악보·음악 세션·경계 대화 이력도 필요하다.
- 기본 후드, 무료 산책, 기본 선택으로 **데이트 7회** 뒤 연인 또는 친구 후일담에 도달한다. 보류한 경로는 **9회**. 실제 소요 분수는 측정하지 않았다.
- 산책 약속에는 만료 기한이 없다. 다른 장소를 방문해도 사라지지 않고, 산책의 마지막 선택까지 마쳤을 때 이행된다. 약속 이행은 별도 누적 기록이며 추가 능력치 보상은 없다.
- 미접속이나 거절로 신뢰가 줄지 않는다. 의상·유료 공연은 진행 필수가 아니다. 구매 자체는 관계를 올리지 않는다.
- 이야기 장면은 추가 시간·돈을 쓰지 않는다. 중간 저장 상태에서는 다른 활동을 막아 장소·코디·날짜가 바뀌는 모순을 방지한다.

## 저장과 구현 위치

- `src/story.js`: 직접 작성한 대본, 선택 효과, 사건 조건, 관계 표시, 서사 저장 검증.
- `src/engine.js`: 출발 시 비용 예약, 선택 단계 검사, 마지막 단계에서 일괄 결과 적용. 같은 단계의 중복 클릭·재완료 방지.
- `src/app.js` / `src/story.css`: 대화·응답·회상·관계 화면·반응형 읽기 환경. 지원하지 않는 의상의 표정은 기존 동일 의상의 기본 표정으로 대체.
- 저장 버전 2를 유지하고 `story.revision=1` 추가. 구버전은 경제·의상·기존 추억을 유지하고 서사만 초기화한다. 예전 데이트에 존재하지 않았던 선택을 만들어내지 않는다. 따라서 과거 데이트 횟수는 새 사건 조건에 소급 산입하지 않는다.
- 진행 중 대화는 마지막으로 선택한 단계까지 저장한다. 닫기·타이틀 복귀·새로고침 뒤 이어갈 수 있다. 완료한 사건은 영구 보존, 데이트 앨범은 기존대로 최근 60회, 활동 기록은 200건.

## 검증과 남은 범위

Chrome/Windows 실제 실행: 엔진 22건, 서사 규칙 13건, 저장 장애 4건, 기존 UI 10건×2폭, 코디 UI 8건×2폭, 신규 서사 UI 6건×2폭 = **87건 통과**. 별도로 실제 Tab·Enter·Esc 입력을 각 화면 폭에서 검사한 **6건도 통과하여 총 93건**이다. 1440px·390px에서 새 게임부터 후일담까지 실제 DOM 버튼으로 진행, 중간 새로고침·앨범 무변경·무료 경로·글자 크기 21px·가로 넘침·이미지 로딩을 검사했다. 3,000회 무작위 행동 불변식과 34개 PNG 디코딩도 기존 검사에 포함된다. 기록: `qa/narrative-*.txt`, `qa/narrative-*.png`.

실제 휴대전화, Safari/Firefox, 스크린리더 낭독, 음향 청취, 일반 이용자의 장기 재미 평가는 이번 검증 범위가 아니다. 3개의 반복 데이트 대본을 기반으로 회상 문구를 추가하는 구조이므로 무한한 새 대화를 제공하지 않는다. 수련의 독립 시간표·날씨·방송·팬덤·미니게임·다중 연애 상대는 추가하지 않았다. 상용 완성작과 대등한 콘텐츠량이나 ‘완벽한 밸런스’를 의미하지 않는다.

## 플러그인 적용 기록

- GameFinder `find_game`을 먼저 호출했으나 `Connection failed / UNAVAILABLE`. 추천 결과를 받은 것으로 표시하지 않으며 공식 자료로 비교를 보완했다.
- Game Studio: 기존 DOM 스택 보존, 핵심 플레이 흐름과 입력·상태 피드백 검토, game-playtest 지침에 따른 브라우저 QA.
- Web Game Builder: 상태/콘텐츠/UI 분리, 저장·재개·접근성·PC/모바일 확인에 적용.
- Game Development Studio: 라우팅 지침 확인. `game-dev` 명령이 PATH에서 발견되지 않았고, 이번 구현은 새 에셋 생산·벤더링·GPU 진단·성능 최적화 작업에 해당하지 않아 CLI 작업은 실행하지 않았다. 기존 이미지와 일반 브라우저 검사만 사용했다.
